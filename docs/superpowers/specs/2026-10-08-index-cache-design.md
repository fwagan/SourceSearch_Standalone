# 第4阶段：索引缓存与增量更新

用户已要求开始推进第4阶段；基于原需求（Git才支持缓存、repo+branch、增量、管理器）及当前源码制定。沿用当前执行和本地提交授权。每批100条、高亮及已接受性能基线不变。

## 行为

Git目录首次打开无缓存时提示建立；已有缓存时检查文件集合与元数据，自动加载或增量更新，完成后允许搜索。切换目录/分支清空旧结果并匹配新身份。普通目录和Git身份未知时可手动建立临时快照，不注册可自动复用的缓存。窗口激活检查Git身份；同身份文件修改通过“更新索引”手动检查，不做文件监听或每次激活全扫描。提供“完整重建”兜底。

缓存键包括规范化仓库绝对路径、选中的目录、分支（游离HEAD使用提交SHA）、索引格式版本、后缀集合和大小限制。分支区分大小写，Windows路径不区分；同名不同仓库/子目录不能混用。分支缓存反映工作区内容，包括未提交文件，不声称仅对应某个commit。

建立前后读取身份；身份变化或从可识别变为未知则拒绝发布。已存在缓存仍保存，但当前上下文禁止搜索旧身份。损坏缓存明确提示并允许完整重建；不要把损坏误报为没有缓存。

## 增量算法与一致性

选择复制后更新Lucene快照：保留原索引，复制索引文件到新GUID目录，按文件键删除变更/消失文档，仅重新读取并分词变更文件。备选原地修改节省复制但回滚/并发风险高；逐文件独立索引会扩大查询与管理复杂度，本阶段不采用。

重新按现有Git忽略/子模块/后缀规则枚举。比较每文件LastWriteUtc+Bytes，时间相同且大小相同则复用。元数据变化时读取内容并用SHA256判断是否只改变时间；新增读入，删除/忽略/不支持或读取失败的旧文件从新快照移除，并记录跳过原因。重命名视为删除+新增。上次跳过文件重新尝试读取。元数据快检不能发现“同大小且人为恢复时间戳”的内容变化，完整重建用于此场景。

稳定file_id允许删除后的空洞，通过Id映射解析路径；schema2增加可删除文件键，旧schema1仍可显式只读打开，但不自动认领为分支缓存。新建/更新前后保持原source只读。取消/失败不替换索引指针，不损坏旧快照；缺少completed的目录不被加载。

缓存元数据用同目录临时文件+原子替换发布。每键进程间独占操作锁防止同时发布/删除，快照读租约防止删除使用中的索引。删除只针对工具自有缓存键目录，验证路径和拒绝reparse point；管理器执行用户选择的删除，程序不主动批量清理旧版本。失败半成品仍可通过删除该缓存项清理。

## UI与存储

存储暂沿用工具artifacts/indexes，Git缓存位于cache/<key>/snapshots/<guid>及entry.json；普通目录仍在ui/<guid>。后续安装阶段再迁移用户数据目录，不同时改变安装部署模型。

顶部“索引缓存”打开管理器，显示目录、分支、最后建立时间、当前快照大小/状态；支持刷新、删除所选（确认；使用中拒绝），不checkout分支。主窗口提供更新索引/完整重建，状态显示正在检查、复用或更新统计。已有未变化缓存可直接复用，无需重新读取未变化源码。缓存不存在时不自动全量建立，避免选择目录就启动长任务。
