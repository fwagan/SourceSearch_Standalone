# Source Search 产品界面设计 · 第 2 阶段

日期：2026-10-08。状态：设计稿，待用户评审；不是已实现功能。基线：`e24bd42`，第 1 阶段拆分完成。

## 1. 目标与已确认约束

用户决定以现有 MVP 推进独立 Windows 产品，采用 MaterialDesign；本次明确选择**优先深色紧凑**。保留上下三层：索引管理、搜索条件、结果表格。结果只有文件全路径和匹配行，不增加类名列。快速索引检索、默认包含匹配、可选全字匹配及包含/排除后缀过滤是既定能力。

本阶段交付可评审的设计及交互示意。下一阶段在现有 WPF/Presentation/Core 上实现。分支持久缓存、增量更新和缓存管理器属于第 4 阶段。第 3 阶段只增加显示身份所需的轻量 Git 元数据读取，不进行 checkout、拉取或缓存复用。

当前建议（尚未作为用户已确认需求）：继续按 Enter/按钮提交查询；第一版不做输入即搜；采用紧凑 Material 控件而非大面积卡片；高亮当前已提交查询的命中；支持 Ctrl+F 聚焦搜索。浅色主题后置。

## 2. 布局选择

| 方案 | 优点 | 代价 | 决定 |
|---|---|---|---|
| 紧凑三层工具界面 | 符合原始结构，结果面积大，操作固定可见 | 设置增多时需另设弹窗 | 推荐 |
| 左侧索引导航 + 右侧搜索 | 多仓库切换方便 | 当前只有一个目录，导航浪费横向空间 | 暂不采用 |
| 大卡片/宽松表单 | 初次使用醒目 | 压缩代码结果，鼠标移动更多 | 暂不采用 |

交互示意：`docs/design/source-search-dark.html`，离线、无依赖、只使用合成数据。它验证布局和状态表达，不是 WPF 截图，也不作为实际搜索、虚拟化、DPI或性能的证据。页面顶部“预览状态”及底部说明属于评审工具，不进入正式程序。

## 3. 视觉基线

- 默认窗口 1180×780 DIP，最小 880×600 DIP；保留 Windows 原生标题栏、缩放和系统菜单，标题改为 Source Search。
- 深灰背景 `#121417`，顶栏 `#1B1E23`，输入/表格区域 `#171A1F`，边界 `#353B45`；正文 `#E4E8EF`，次要文字 `#A5AFBD`。浅蓝主色 `#ADC6FF`，主按钮深色文字 `#102E60`。
- 成功/警告/失败同时有文字，不只依赖绿/黄/红。焦点轮廓清晰；禁用与只读可区分。
- 界面字体 Segoe UI / 系统中文回退，正文 13–14 DIP；代码 Consolas/Cascadia Mono，14 DIP；结果行高 28–30 DIP，工具按钮 32–34 DIP，搜索输入 40 DIP。字体缩放和125%/150% DPI下不得截断文字。
- 外边距 16–18 DIP，组间距 12–16 DIP，控件间距 8 DIP。使用细分隔线、少量圆角，不给每一组包装卡片。取消结果表格竖网格线。
- 限制动画与阴影；结果行不做进入动画，不附加每行菜单按钮、复杂控件或持续动画。
- 上述颜色是产品语义资源，实施时映射 MaterialDesign 主题资源，不逐控件散落硬编码。MaterialDesign 2/3 的具体字典及包版本由第 3 阶段短探针确定并锁定；不同默认密度不得破坏本稿尺寸目标。

## 4. 三层结构

### 索引管理区

左侧第一行：文件夹短名称、分支标识；第二行：完整路径（空间不足截断，悬停可见完整路径）。右侧：带文字的索引状态、“选择文件夹”、“建立/重建索引”；建立时将建立按钮替换为“取消建立”。

下一行显示文件数、行数、索引建立时间以及“详情”入口。建立中改为已处理/已索引/跳过数，使用不定进度条，不编造总量或百分比。详情是实际 BuildReport 的只读摘要与跳过原因/路径列表，大列表同样虚拟化。

Git 正常分支显示短名称；detached HEAD 显示短提交号并标注游离状态；未出生分支保留分支名；非 Git 目录显示“非 Git 文件夹”；识别失败显示“分支未识别”，详情保留原因。元数据来自所选路径所属仓库，不用工具仓库的分支替代。子模块索引内容延续既有枚举策略，顶栏不冒充逐子模块分支列表。

缓存管理器未来放在这一行最右侧。第 3 阶段不放可点击的空壳，也不展示一排“尚未实现”按钮；第 4 阶段具备功能时接入。

### 搜索区

第一行：宽搜索框 + 高强调“搜索”按钮 + “全字匹配”复选框。默认包含匹配，保留大小写不敏感、字面量及 Unicode 边界契约。占位文字“搜索代码、标识符或文本”，说明文字“Enter 搜索 · 默认包含匹配，不区分大小写”。

第二行：两组 checkbox + textbox，分别为“仅包含文件类型”和“排除文件类型”；宽窗口左右并排，较窄窗口上下排列。复选框决定文本框是否可编辑；取消勾选保留输入值。逗号分隔、不区分大小写、包含与排除重叠时排除优先，空列表不限制；不引入通配符。

提交方式继续使用 Enter 或按钮。Ctrl+F 聚焦并全选搜索文本。条件改变仅使续页失效，不触发扫描/重建，也不取消建立任务；保留旧结果时明确显示“条件已更改，按 Enter 搜索”，结果标题仍显示**上次已提交**的查询条件。空查询禁用搜索，不把空查询当全部文件；输入换行提示当前仅支持单行查询。

### 结果区

占剩余空间，上方一行显示已提交查询、模式和“已显示 N 条”；不要把首批数量写成总命中数。底部显示快照提示和“加载下 100 条”。到末尾显示“已到末尾”；达到 1000 行显示“达到显示上限，请缩小搜索范围”，不继续加载。

两列：文件全路径约42%，匹配行约58%，允许拖动列宽，不允许按列全局排序。长路径单行省略，悬停给出完整值；提供“复制完整路径”操作。匹配行在同一列内先显示弱化行号，再显示代码；不增加独立类名列。

命中高亮使用 Core 返回的原始文本偏移，基于该批结果的请求，不基于正在编辑的输入。只为实际可见的行创建简单文本片段，不引入语法解析或代码编辑器控件。保持前2000 UTF-16字符的显示限制和截断提示，高亮裁剪到展示范围，不能改变实际查询结果。未显示的后半行命中不得伪造为可见命中。

不要求精确总量、全量排序或即时统计。单次100条、上限1000、虚拟化、异步查询及取消保持。行选中必须清晰，方向键按标准表格行为移动。编辑器跳转、文件预览面板、多标签搜索在后续单独评估。

## 5. 状态与恢复规则

| 状态 | 表达 | 可用操作 / 结果行为 |
|---|---|---|
| 无索引 | 尚未建立；结果区提示先建立 | 可改条件/目录和建立；禁用搜索/续页 |
| 建立中 | 不定进度 + 实际文件计数 | 可编辑查询；禁用换目录/重复建立/搜索；可取消 |
| 就绪、未查询 | 文件数量/时间；结果区提示输入搜索文本 | 可搜索、重建、换目录 |
| 查询中 | 结果栏轻量“搜索中”状态；提供取消查询 | 可提交新查询淘汰旧查询；禁用续页；不弹遮挡对话框 |
| 有结果 | 已提交条件、已显示数量、匹配行 | 可续页至上限、重新搜索；未知总量不显示总量 |
| 无结果 | “没有匹配结果”，提示调整文本/模式/过滤 | 条件保留，允许继续搜索 |
| 查询失败 | 结果区错误及可恢复提示 | 旧结果如保留则标明旧条件；续页失效；可重试 |
| 建立失败/取消、无旧快照 | 明确失败/取消原因，无可搜索索引 | 可重试；禁用搜索 |
| 同目录且Git身份未变，重建失败/取消、有旧快照 | “正在使用建立于…的旧快照” | 允许搜索旧快照；保留其真实路径/分支/时间 |
| 换目录 | 新目录“尚未建立” | 清空旧结果并释放旧目录活动快照；不得在新目录标签下搜索旧内容 |
| 外部切换分支或HEAD身份变化 | 当前分支与索引来源不同，“需要重建” | 清空旧结果、禁用搜索与续页，重新建立；不替用户checkout |
| 源文件编辑（同一HEAD） | 一直明确“结果来自索引快照” | 此阶段不监听工作树，用户手动重建；不能宣称自动过期检测 |

选择相同规范化目录不清除快照。选择器取消不改变任何状态。失败状态必须区分“当前选中目录/分支”和“仍可使用的旧索引来源”，禁止用一个拼接状态字符串充当身份来源。

分支元数据在打开目录、建立前后、窗口重新激活时异步读取；去重在途请求，旧元数据回复不得覆盖新目录。若建立前后识别到分支/HEAD变化，索引不标记为当前分支就绪，要求重建；此时即使有旧快照也不能恢复搜索资格。无法识别时明确标记未知，不虚构分支，也不声称验证了分支一致性；普通目录和Git识别不可用时仍允许按手动快照模式检索。无需每次查询调用 Git，不扫描完整工作树状态。

切换目录/关闭窗口需等待在途查询释放 reader，原有取消和快照隔离契约保持。重建同目录失败保留旧快照；切换至其他目录后建立失败不自动恢复到旧目录，以免混淆搜索范围。

## 6. 第 3 阶段落地边界

| 层 | 改动方向 |
|---|---|
| Desktop | MaterialDesignThemes、语义资源、紧凑控件样式、布局、命中呈现、只读详情和原生选择器 |
| Presentation | 将状态/错误/数量/已提交条件拆为结构化属性；完整路径和行号/展示片段；查询命令状态、快捷键和目录切换生命周期 |
| Core/外围元数据适配 | 复用倒排查询与索引格式；提供只读 Git 身份适配以及清理/隔离旧上下文所需的最小生命周期支持 |
| UiValidation | 加载与正式程序相同的主题资源，沿用同一窗口/操作路径，补充主题后冒烟与计时 |

不把主题引用放入 Core/Presentation。窗口仍只做平台视图适配，不把业务逻辑搬回 code-behind。细化实施计划时先验证资源加载和 DataGrid 模板，再分步接入布局、结构化状态、交互；不是整体替换检索核心。

## 7. 验收条件

1. 原98项测试保持通过，补充目录切换/分支身份/旧快照状态、高亮偏移及查询编辑与已提交结果分离测试。
2. MaterialDesign 窗口可见冒烟覆盖建索引、取消、查询、过滤值保留、Enter命令、空查询、分页上限、空结果、错误恢复、详情及两种宽度。真实键盘/鼠标、原生目录选择器和125%/150%DPI需要实际检查，不能以HTML代替。
3. 1000行仍虚拟化；禁止逐行重型动画、全表自动内容测宽或每行复杂菜单。
4. 保存相同语料/查询集的改造前后UI测量，包含首次/预热P95和失败组；不把换主题视为性能优化。已有100ms长尾未解决，不能因核心测试通过宣称UI达标。
5. 正式Desktop发布无Validation依赖；UiValidation实际加载同一主题；搜索不触发Git扫描/索引重建。
6. 文件夹、当前分支、索引来源与结果来源一致；缓存管理器、模糊/正则、编辑器跳转与持久缓存未实现前不提供伪功能。
