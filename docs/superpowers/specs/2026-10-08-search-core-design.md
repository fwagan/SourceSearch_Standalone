# Source Search 检索核心与最小验证 UI 设计

日期：2026-10-08。状态：用户已批准（2026-10-08）；本文件记录设计，不代表实现或性能验证已完成。

## 1. 目标与优先级

在独立 Windows 桌面程序中验证类似 Entrian Source Search 的索引检索体验。用户确认：快速响应是 MVP 核心；默认包含匹配，可开启全字匹配；仅需文件全路径和匹配行，不显示类名；后缀包含/排除过滤属于首版；UI 只需能验证功能。

本阶段采用 C#、.NET 10、WPF、Lucene.NET。本机已安装 .NET SDK 10.0.401。索引库版本在实现时固定，不使用浮动依赖；采用源码分词规则，不直接套用自然语言停用词或词干处理。

完成顺序：检索正确性与性能探针 → 最小 UI → 实际样本验收。repo + branch 缓存复用、增量更新、文件监听、缓存管理器、模糊搜索和正则均为后续阶段。

索引文件类型白名单是建立索引的输入范围；UI 的后缀过滤是该范围内的查询条件，改变查询过滤不会重建索引。性能报告必须列明输入范围。

编码支持严格 UTF-8（含 BOM）、带 BOM 的 UTF-16/UTF-32；无 BOM 且 UTF-8 无法解码的文件跳过并报告，不静默替换字符。单文件保护上限先设 32 MiB，超限明确报告；此限制必须写入测试报告。建立索引前后检查文件元数据，变化文件重试一次，仍在变化则记录失败，避免宣称得到了稳定快照。

## 3. 查询契约

- 默认逐行的字面量包含匹配，不解释通配符、正则或 Lucene 查询语法；空查询不执行，换行查询提示暂不支持。
- 默认大小写不敏感，对 Unicode 标量逐个执行 `Rune.ToLowerInvariant`，并保留映射到原始 UTF-16 偏移的关系；查询、词索引和 n-gram 索引共用该规则。不删除重音，不做 Unicode 兼容等价替换，不进行多字符展开。n-gram 长度按 Unicode 标量计数。
- 全字匹配要求命中两侧是行边界或非词字符。词字符定义为 Unicode 字母、组合标记、十进制数字和连接标点（包括下划线）。驼峰不是全字边界。此规则用于文本检索，不声称覆盖每种语言的标识符语法。
- `User` 在默认模式匹配 `User`、`UserService`、`GetUser`、`User_Name`、`User2`；全字模式只匹配这些例子中的独立 `User`，也匹配 `List<User>` 及注释中的独立单词。
- 两种模式都检索注释和字符串，不进行语义分类；单字符、双字符、中文、数字和标点均需正确处理。
- 后缀过滤接受 `cs,.json,xml`，忽略首尾空格、空项和大小写，去重；禁用的条件不起作用；启用但列表为空视为不限制；包含与排除重叠时排除优先。不把通配符解释成文件类型。后缀按最后一个点划分。
- 每个匹配行一条结果，附一基行号；同一行多次命中合并。首批最多 100 条，后续每批 100 条，原型展示上限 1,000 条，提示已达到上限；正确性校验工具可遍历全部结果，不受 UI 上限影响。
- 查询快照来自建立索引时的文本；源文件发生变化后手动重建才能反映，UI 显示该事实及建立时间。

## 4. 索引方案与取舍

选用成熟倒排索引引擎，不自行开发索引文件格式。两种查询模式共用一次构建产生的索引，切换无需重建。

初始实现以文本行为索引文档，保存文件 ID、原始行号和原始文本，文件表保存完整路径、后缀和元数据。长行保持正确性，不截断索引内容；界面可截断展示并标记。

字段规划：

- 完整词字段：按查询契约切分，保留完整标识符，支持全字单词查询。
- 字符片段字段：为规范化后的行内容建立 1、2、3 字符 n-gram 倒排索引，区分片段长度。不枚举任意长度的所有子串。
- 文件类型字段：作为检索过滤条件。
- 存储字段：原始文本、文件 ID、行号；命中确认与展示只读取候选行。

包含查询长度至少为 3 时使用三字符片段筛选候选；1 或 2 字符直接使用对应长度的索引。候选必须进行连续字面量核验，不能把片段共现视为完整字符串命中。全字单词查询优先完整词索引；含空格/标点的查询走字符片段候选并执行同样的全字边界检查。最终偏移映射回原始行，不用规范化字符串的偏移直接截取原文。

源码关键字、短词不能因自然语言停用词策略而消失。核心查询代码显式构造引擎查询，不把用户输入交给 Lucene QueryParser。

不设置查询前目录扫描，不在 UI 线程搜索，不每次打开索引 reader。分批遍历候选，边核验边返回首批，查询顺序采用当前索引内部的稳定顺序，首版不做全量相关性排名、全局路径排序或同步精确总数统计。不能先只取 100 个候选再过滤，导致漏掉后面的真实命中。

比较过的方案：顺序扫描文本不满足本任务的索引要求；SQLite FTS5 trigram 可以处理子串，但短词需要额外设计；Lucene.NET 支持自定义分词与查询路径，作为本轮优先方案。Lucene 的使用本身不代表已达到延迟目标。

主要风险是按行建文档以及 1/2/3-gram 对磁盘、内存和构建时间的放大。因此首先测 C# 范围，再测混合范围。若方案不达标，保留报告并比较以词典片段查找完整词、再访问词位置索引等优化；不能悄悄改成整词搜索或排除短词来宣布通过。

## 5. 程序边界与最小 UI

- Core：文件清单、规范化与词边界、索引构建、查询和结果批次。与 WPF 解耦。
- Validation：确定性测试数据、独立顺序匹配基准、真实语料正确性比较、性能测量和报告。直接扫描仅用于离线校验，不是生产查询回退。
- Desktop：目录框和选择按钮、建立/重建按钮、状态与取消按钮、搜索框与搜索按钮、全字复选框、两组后缀过滤、虚拟化结果表格、耗时和展示数量。

索引状态：未建立、建立中、就绪、失败。只有完整索引才能搜索。新构建写入独立位置，成功后替换当前 reader；失败保留旧快照并标明状态。界面显示已经处理的文件数与跳过数，不承诺未知总量的进度百分比。

回车触发搜索；按钮和回车共用路径；新查询取消旧查询并携带请求代号，过期结果不得覆盖当前结果。显示首批后按需继续加载。允许取消建立和搜索。

最小 UI 不包含索引缓存管理器、分支切换、语法着色、编辑器跳转和复杂布局。后续可在不替换搜索接口的情况下增加这些能力。

## 6. 验证与验收

### 正确性

独立顺序扫描基准以原始行文本实现查询契约，不能复用候选索引逻辑；明确区分共享契约与独立匹配算法。比较文件路径、行号、命中偏移及数量，不只比较首屏。

确定性测试覆盖：完整/部分词、驼峰与下划线、数字、大小写、1/2 字符、中文与组合字符、代理对、重复字符片段、片段共现但不连续、标点和空格、无结果、重复命中、CRLF/LF、末行无换行、UTF BOM、空文件、超长行、路径含空格/中文、后缀条件组合、取消和索引失败。

真实样本分两轮：全部 C#；清点文件定义的混合后缀范围。固定查询集至少包含 30 个查询/模式组合，覆盖 `User`、`Id`、`IO`、`a`、`Service`、`public`、实际存在的长标识符及其中间片段、中文、标点和确定不存在的字符串。两种模式与文件过滤分别测试；根据实际命中分布确认低频和高频组。

### 性能

- 记录 CPU、内存、磁盘、操作系统、.NET/索引库版本和 Release 构建方式。
- 记录实际输入文件数、内容大小、行数、跳过清单、样本内容摘要；构建耗时、索引大小、进程峰值内存。
- 每个固定查询组合预热 5 次、计时至少 30 次，输出逐查询 P50/P95/最大耗时，不能只给总体平均值。
- 目标：在此电脑和上述语料下，预热查询从提交到首批最多 100 个真实命中在 UI 呈现的 P95 不超过 100 ms。核心引擎延迟与 UI 延迟分别测量；CLI 结果不能冒充 UI 结果。
- 单独记录进程启动、索引打开和首次查询；不通过伪造系统冷缓存声称磁盘冷启动。短词、高频词、无结果和长行相关查询分别报告，失败项不能混入平均数隐藏。
- UI 不等待精确总数，不把候选数量当匹配数量。索引建立期间、冷启动和全量导出不适用 100 ms 首屏目标。

通过条件：约定语义的正确性校验通过，两轮语料均达到约定的预热首屏目标，UI 可重复运行验证，且构建成本与资源占用有实际数据。若性能未达标，应报告具体失败组与瓶颈，不能宣称核心验证完成。
