# 产品化第一阶段验证（2026-10-08）

基线 `fffbc10`，分支 `codex/product-stage1`。本阶段将 MVP 整理为可继续改造的结构，保持现有布局、搜索语义和索引格式，没有引入 MaterialDesign、分支缓存或增量重建。

## 改动

- 新增无 WPF 依赖的 Presentation 项目，集中建立索引、搜索、分页、状态及取消逻辑。窗口通过命令绑定操作；目录选择、WPF 呈现检查点及关闭适配仍在 Desktop。
- UI 冒烟和基准迁入独立 UiValidation 宿主，继续复用正式窗口及操作逻辑；Desktop 不引用 Validation/UiValidation。脚本入口同步迁移。
- 禁用包含/排除条件后，搜索保留控件原值；重新启用即可继续使用。
- 不存在的 gitlink 目录报告 `SubmoduleNotInitialized`；固定排除目录仍不产生诊断。
- 呈现失败后禁用续页，避免新结果复用旧分页游标。

新增测试先观察失败再实现，覆盖查询竞争、建立期间编辑条件、失败/取消保留旧快照、命令状态、关闭、过滤原值、分页上限/失效、缺失子模块及排除规则。架构测试递归检查 Desktop 项目引用链不含验证项目。

UI 冒烟检查实际按钮/Enter 绑定指向同一命令，并执行命令及共用查询路径。其余检查包括100行首批、1000行上限、一次批次通知、虚拟化和最小化使测量无效。它不等同于真实鼠标/键盘输入事件测试；目录选择对话框和物理按键仍待人工验证。

夹具为3个文件、1107行，33/36组超过100ms，最慢 P95 为309.94ms。这个测量只验证宿主迁移后的完整流程及失败退出码，不能推导大仓库性能，不能宣称 UI 长尾已解决，也没有排除相对基线的性能回退。本阶段没有重建或重测真实语料，原报告保持为 MVP 历史基线。

本地证据：`.tmp/stage1/` 中构建、RED/GREEN测试日志；`artifacts/reports/ui-smoke.json`、`ui-smoke.png`；`artifacts/reports/stage1/{queries,ui-timings}.json`。源码正文和运行时快照仍只保存在忽略目录中。

## 实施取舍

延续原任务的 PowerShell 流程记录，避免重复调用已失败的 Bash 辅助脚本；代价是手动维护任务记录。复用原 checkout 中的专用分支，保留 MVP 分支与提交；代价是没有第二份 checkout 隔离。

独立只读审核发现1项 Important、无 Critical/Minor：缺失子模块的上级目录也不存在时，诊断仍会误报。已补充5个失败用例，覆盖多级缺失目录、嵌套排除目录和符号链接祖先，再修改为先检查祖先范围/排除/链接，允许子模块路径缺失但不掩盖其他IO异常。5项均 RED→GREEN，最终98项测试全部通过。

审核未作判断的范围明确保留：实体点击/键盘路由需后续人工验证（代价是输入路由缺陷可能未被发现）；P95不视为验收通过（代价是响应长尾仍存在，回退尚未排除）；源码目录定位、持久缓存与增量索引仍按原阶段规划推进（代价是当前版本不便独立安装，启动后仍需手动建索引）。无新增延期 Minor。
