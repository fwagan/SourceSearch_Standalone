## 正确性

36组固定查询覆盖完整词、标识符片段、1/2字符短词、中文、字面量标点、零命中和后缀组合，两种匹配模式都参与。独立 scalar oracle 不复用产品的归一化、边界或匹配实现。逐文件校验 SHA-256 保证与索引快照一致；比较所有结果行（不限1000）、原始正文、行号、原文匹配偏移及重复命中数。

大结果集以 SHA-256 多重集摘要、行数和匹配数比较，避免在内存保存数百万结果；保留极小的摘要碰撞风险。两份 summary 的 `CorrectnessPassed` 和逐查询 `Correct` 是最终实测结论。

## 性能问题及修正

最初 C# 全组核心 P95≤55.49ms；混合范围有三组未达标：`a.b` 全字1663.87ms、`MetricsCollector` 包含997.36ms、`ricsColl` 包含994.73ms。不是每次遍历全部源文件：这三组分别访问2,878、104、112个倒排候选行，但其中包含很长的压缩JS行。

诊断显示候选正文共约5,296万、2,945万、3,129万字符，最长单行1,195,533字符。预热后的 stored-field 读取约161–393ms，归一化和匹配约617–1281ms。旧实现对每个标量分配字符串并为整行创建两组偏移数组，百万字符无命中行分配约44MB。

修正包括：分块 SIMD ASCII 小写、Unicode 标量原语义不变；UTF-16宽度不变时直接使用原文偏移，宽度变化保留映射回退；每快照按 LRU 保存已解码正文及归一化文本，估算保留容量上限256MiB。没有缓存查询结果，没有修改索引格式或查询语义。关闭快照释放缓存；并发在途请求临时内存不算在保留容量内。

分配量、全部有效Unicode标量、无缓存/小缓存一致性与容量限制均有回归测试。相同索引和相同三条查询的定向复测 P95 为12.84/6.69/5.46ms。完整36组复测以各 summary 和逐查询表为准，优化前的全部30次样本同时保留。
