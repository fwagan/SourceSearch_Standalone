# 实施取舍与审核结果

用户已批准提交并执行计划；本次只进行本地实现与提交，保留 `feature/search-core-mvp` 分支，没有远端推送、合并或部署。

1. 原生worktree创建遇到仓库所有者检查失败，在干净的原工作区专用分支实施。代价是没有第二份checkout隔离。
2. 技能的Bash辅助脚本不能解析basename/dirname，改用PowerShell保留任务记录和RED/GREEN日志。代价是人工维护流程记录。
3. 根据Git index中的gitlink识别子模块，未解析.gitmodules声明。代价是只声明但未进入Git index的模块不遍历。
4. 后缀集合以每层最多32个分支的OR查询树表达，没有增加TermsFilter依赖。代价是极大后缀集合增加查询树开销。
5. 全量独立正确性比较用SHA-256多重集摘要、行数和命中数控制内存。代价是极小摘要碰撞风险，以及差异定位不如保存所有结果具体。
6. 耗时建索引期间用独立构建目录开发UI。代价是构建耗时和资源峰值可能受开发负载影响；正式查询计时未与编译、其他基准并行。
7. Windows自动点击工具初始化失败后，使用应用内可见窗口冒烟和WPF渲染截图。代价是真实点击/按键路由仍未实测。
8. 为超长候选行增加每快照约256MiB的有界解码/归一化LRU，并加速ASCII归一化。代价是保留内存增加，冷查询仍可能慢；所有首次与暖查询数据分开报告。

独立只读审核发现三个Important，全部修复：查询编辑误取消构建；驱动器/UNC根目录的错误边界；Git子目录未继承忽略规则。相关回归先失败后通过，最终82项测试全通过。早期“所选目录无自身.git即普通目录”的实现已被第三项修复替代。

MVP 当时延期的两项Minor（禁用过滤值丢失、缺失子模块诊断不准确）已在后续[产品化第一阶段](../product-stage1.md)修复。本文其余内容是 MVP 实施的历史记录。

审核期间暂不判断的性能结果现已补齐：核心通过，UI目标未全面通过。真实输入路由限制、从源码目录运行、缓存管理/增量/正则/模糊延期都在交付报告中保留，没有默认为已完成。
