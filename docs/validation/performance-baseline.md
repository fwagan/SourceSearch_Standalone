## 后续比较规则

后续性能变化以这两份完整的逐组测量为参照，尽量保持相同快照、查询集、批次、窗口尺寸、主题、高亮和测量环境。比较各组P50/P95、首次查询和峰值工作集，记录环境与语料变化；上表的最慢P95是摘要，不作为所有查询共享的宽松阈值。

原“每组P95≤100ms”不再作为当前UI阶段或进入缓存阶段的阻断条件；本次退化已获用户接受，可以按原顺序继续第4阶段缓存与增量更新。优化仍可后续推进。本次接受不意味着未来进一步退化自动获得接受，也不改变搜索正确性、取消、虚拟化等功能要求。

原始报告中的 `Passed:false` 表示未达到当时100ms目标，保留原值以维护测量事实；它与现在的“基线已接受”是不同状态。现有基准程序/脚本仍执行旧的100ms诊断检查，因而可能返回非零；不要把这一退出码单独当作新基线回归结论。此次仅更新验收依据，未修改基准程序、搜索算法或界面。

窗口不可见/最小化、渲染超时或样本不足的测量仍无效；`csharp-invalid-window.json`不属于基线。接受性能基线也不代表物理键鼠、物理DPI和发行安装验证已完成。
